# Settings coverage map

Every declared AppConfig key is assigned below. This is a proposed information architecture, not a schema migration. Native constraints and enum definitions in src/shared/types.ts, configConstraints.ts, configKeys.ts and aria2Options.json remain authoritative. No compatibility aliases or speculative preferences are introduced.

The four top-level categories are Appearance and behavior, Downloads and storage, Network and connections, and Advanced. Contextual tools (file rules, User-Agent manager, BT/eD2k) open within the right pane or a bounded dialog, never a permanent third navigation column.

The first appearance mockup proposes immediate saves only for individually reversible UI choices. Existing grouped form saves, hot updates, persistence and rollback must remain transactional. Restarts depend on current native/source capability metadata, not on a hardcoded assumption that every port behaves identically.

## Nested fields

- proxy: mode, server, username, password, bypass and scope stay together; password masked and explicit reveal/copy only.
- clipboard: enable, http, sftp, magnet, ed2k, thunder and btHash; preserve individual filters when master is off.
- portConflictRecovery: enabled, rangeStart, rangeEnd and rpc/extensionApi/bt/ed2k/ed2kUdp scopes; validate range ordering natively and in form.
- fileCategories: label, extensions, urlPatterns, urlPatternMode, directory and builtIn; built-in deletion restrictions remain.
- userAgentProfiles: id, name, value and creation/update timestamps; userAgentRules: id, enabled, hostPattern, profileId, overridePlugin. Do not expose generated IDs as editing fields.
- taskSort and taskManualOrder remain per-scope, preserving existing supported fields and values.

## Validation source

Do not copy generated numeric ranges into code. Use configConstraints.ts and source enums. In particular, concurrent tasks allow 1–100 and stream connections allow 1–256; image 13 was corrected to those values. Schedule day values and sync interval presets follow the existing validators. The words “automatic” or “recommended” may only describe an actual supported option.

## Native actions outside AppConfig

Database reset, engine restart/recovery, reveal/open paths, tracker/bootstrap/blocklist synchronization, system proxy detection, content inspection and update install are commands rather than plain settings values. Their pending/error/confirmation states follow FLOWS.md. Database reset clears history, receipts and website credentials and restarts; no ordinary preference toggle can invoke it.
